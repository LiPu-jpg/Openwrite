## 一、作品名称

**openwrite-novel-swarm：多智能体协同的长篇小说创作蜂群**

## 二、项目简介

长篇创作是单 Agent 的公认短板：写长了忘设定、审自己的稿看不出漏洞、改一处崩三处。openwrite-novel-swarm 把成熟的 OpenWrite 长篇小说引擎（六域评审 DAG、伏笔图谱、正典 truth 文件、风格指纹体系）**整体迁入 openJiuwen 原生框架**——不是外挂，而是框架、蜂群、编排、技能、工具全部原生，仅 6.4 万行领域引擎作为被治理的能力经 MCP 接入：

- **规划师**定骨架（人物 / 世界观 / 卷幕节章四级大纲），产出全书唯一规划真源；
- **主笔**只按已确认骨架施工，动笔前先经 MCP 拉取引擎实时上下文包；
- **三名隔离评审**并行覆盖六域（连贯逻辑、正典资料 / 情节承诺、节奏场景 / 角色关系、文风表达），评审协议与引擎 **47 节点锁定评审蓝图（topology_locked）同构**——蜂群评的就是引擎评的；
- **修订匠**只做"评审意见要求的最小手术"，判为资产级重写时**拒绝硬改**并回退人工；
- **作者确认门**（HITL）卡在大纲定稿与修订应用两处关键节点，成稿入引擎书稿还要过**指纹接纳门**，人始终掌舵。

写不出长篇的不是模型，是单打独斗的架构。本作品用 Coordination Engineering 回答一个真实痛点：**质量来自分工与对抗，不来自更大的上下文**。

## 三、应用场景说明

- **目标用户**：网文作者、独立写作者、内容工作室、IP 孵化团队；以及需要长程一致文本的机构（游戏剧情文案、剧本工坊）。
- **需求痛点**：单 Agent 创作在数万字尺度上出现设定漂移、伏笔丢失、自审失效；人工审稿成本高且难以覆盖全书一致性。
- **落地形态**：JiuwenSwarm 集群模式下的团队技能（Swarm Skill，已装入原生 workspace），可对话驱动，也可经 SwarmFlow 脚本无人值守批量产章（对应网文日更场景）；创作流程可沉淀为 Swarm Skill 发布到 Skills Hub 复用。
- **方向归属**：大赛「办公」方向（文档处理 / 知识管理 / 流程自动化范畴的长文内容生产）。

## 四、技术方案

**架构**：混合模式蜂群 = 专精流水线（C）+ 并行分解（B）+ 写审对抗隔离（A），底座为 openJiuwen 原生三件套。

1. **确定性编排**：Leader 只做派发与确定性聚合（blocker 计数、最低域分、覆盖完整性），不写作文本、不替人做决定；完整拓扑以 Markdown 规范（workflow.md/bind.md）与可执行 SwarmFlow 脚本（scripts/workflow.py）双形态交付，二者严格同构。Leader 内含**确定性输入装配**：运行时由 openwrite-mcp 的 `get_outline`/`get_context_packet`/`get_chapter_foreshadowing` 填充写作/评审槽位，独立执行时从规划资产包同构提取。
2. **质量门禁继承 OpenWrite 评审 DAG**：六域划分与"域评分 + 证据 + blocker + 硬门禁"语义来自 OpenWrite `review-dag-framework.v1`（47 节点固定拓扑、rubric v2，蓝图经 `get_review_framework` 原样下发给评审员），未过域定向复评（不回炉全量），修订上限 2 轮，超限降级为带 blocker 的人工交付。
3. **资产单一所有权**：大纲/人物/世界观仅规划师可写，正文基线仅主笔与修订匠（经作者门后）可写，设定级异议一律 planner-return 回流，杜绝多 Agent 并发改乱资产。
4. **引擎确认门全链路 MCP 化（25 工具）**：读路径 8 个 + 写路径 17 个——蜂群成稿入库与接纳门（`save_external_chapter`/`manuscript_status`/`accept_manuscript` 两阶段指纹门/`resume_acceptance` 引擎托管事实重建/`acknowledge_impacts` 作者复核）、引擎原生写审（`write_chapter`/`review_chapter`，实测 87.4 分 pass）、修订提案门（`list`/`apply` 两阶段+冲突重验/`reject`）、**规划写回**（`create_project`/`save_foundation_draft`/`promote_foundation`/`save_outline_draft`/`promote_outline`/`stage_outline_edits`，全部两阶段门 + revision 重验）、`export_book` EPUB 导出校验。**不绕门**：所有写操作对接引擎既有确认门。
5. **HITL 与无人值守双模式**：作者确认门以 approval args 表达；批量模式可关门自动跑，报告逐章标注 UNATTENDED。
6. **知识资产全量迁移**：OpenWrite 12 个子技能按 Skills 规范改写（伏笔状态机、truth 核对清单、tiered-hierarchical-v2 四级压缩、六阶段工作流、patch 纪律等领域真知识全保留），全部装入 JiuwenSwarm 原生 skills 目录。
7. **工程验证**：
   - 官方 swarmskill-creator 校验器 0 error；桩件端到端 18 项断言覆盖六类场景全通过；
   - **真实模型（DeepSeek）端到端**：规划→写作→三评审并行→聚合→交付全链路 5 次模型调用 / 约 30 秒，六域评分 7–9 分；六域评分全过直达交付；
   - **对抗实录**：主笔临场换主角换场景（写了一个无关故事），三评审全部抓出 7 条 blocker，修订匠判定属资产级重写拒绝硬改——分工与对抗的真实威力；
   - **引擎确认门实录**：蜂群成稿写入→指纹门两阶段确认→事实重建（8 影响域全部 current）→作者复核→EPUB 导出校验通过；引擎原生写章同链路自动结算接纳；引擎原生评审 ch_002 实测 87.4 分 pass。
   - **全运行时整跑（2026-10-08）**：jiuwenswarm 真实网关 + agent server 下对话驱动，Agent 自主调用 openwrite-mcp（list_projects / get_review_framework）并正确复述 47 节点锁定拓扑与项目进度；运行时技能清单实测加载 12 个改写技能。排障记录：模型 env 须写入 `~/.jiuwenswarm/config/.env`（常驻网关进程启动时读取，shell 导出无效），原文件为出厂占位值。
   - **旗舰 DEMO《夜班便利店》**（真实新书全链路）：蜂群规划 → 引擎建书（create_project）→ 设定/大纲两阶段门 → 蜂群产章入库 → 指纹门 → 事实重建 → 作者复核 → **引擎原生续写第二章**（30.6 秒，完美承接蜂群正文：备忘录、3号冰柜等伏笔全部接上）→ 双章 EPUB 校验通过——蜂群与引擎同写一个故事的完整闭环。

**代码与文档**：符合 Swarm Skill 规范的技能包（SKILL.md + 7 角色 + workflow/bind/dependencies + 可执行编排 + 测试）+ openwrite-mcp（25 工具）+ 12 个改写技能 + 迁移计划文档。
