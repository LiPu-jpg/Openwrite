# 选区与中断升级补修

本轮对应未发布候选 0.2.28 / Core 5.8.19；公开版本仍为 0.2.27。来自已关闭报告的相关路径复查，四个问题均先独立复现，再加入回归。

| 问题 | 修复后行为 | 验证 |
| --- | --- | --- |
| CRLF 或混合行尾在编辑器内变成 LF，选区错位或原文不匹配 | 根据完整原文与编辑器文本映射行尾边界，发送保存文件的原始片段 | 原生面板与 wheel 内独立 Studio 两条界面路径、真实 HTTP 多行选区 |
| emoji 等字符的 JavaScript UTF-16 与 Python 字符索引不一致 | 请求使用原文 Unicode 码点坐标，批注也按原文坐标映射；重复句仍命中所选的那次 | emoji 前缀、第二次重复句、混合行尾与无末尾换行组合 |
| 升级中断后 active profile 已移走，恢复脚本找不到依赖 | 恢复使用与正常升级互斥的原生文件锁，无须从已移走的 profile 加载依赖；恢复前核对备份清单指纹 | 独立脚本、失效依赖链接、锁互斥/心跳/陈旧锁和修改备份拒绝 |
| 被中断的缓存写入留下不完整 tgz，重试永久冲突 | 完整写入并校验临时文件，再原子替换损坏缓存 | 预置部分缓存后重试成功，校验包指纹及临时文件清理 |

映射只容许换行表示不同；正文编辑、普通空格与 NBSP 差别、半个代理对或半个 CRLF 边界均拒绝，不做模糊匹配。提交修订时另带整篇 revision：即使选区外正文变化，也在调用生成器前返回 DOCUMENT_CONFLICT，现有文件保持原样。两端共用映射源，docs:check 校验 wheel 中生成字节。

本地验证：Core 全量 1542 passed / 32 skipped，修订服务与真实 HTTP 23 passed，原生预设/升级/运行时 40 passed，managed 33 passed，界面 319 passed，插件完整检查通过。独立 Studio 用打包 wheel 内的实际绑定代码测试隐藏 textarea 的换行规范化；HTTP 用实际两端映射模块发送请求。测试使用隔离自动化目录，未调用模型。

跨平台最终结果及确切来源在 [发布验收](RELEASE_ACCEPTANCE.md) 记录。#123 的宿主正式发布与 Android/Termux 真机验证仍未完成，本轮修复不解除发布暂停。
