## #150 / #151 / #142：宿主 rc.4 / rc.5 被版本闸门拒绝

`package.json` 的 `peerDependencies`（`@deepseek-ai/dsh-*`）范围后拒绝加载，

新增这两个宿主的客户端验收，并保留各自的 `--before` 截止时间，
避免上游部分发布时把更新的依赖批次带进旧宿主验收。

`0.1.2-rc.1`、`0.1.5-alpha.1`、`0.2.0-rc.2`、`0.2.1-rc.2`、`0.2.1-rc.3` 的 peer 匹配集合

## #149：新建会话选择器里的 27 条「历史会话」别名

0.2.26 为修 #105 引入「旧 id 作别名」，`preset-definition.mjs` 里硬编码了全部已发布版本号，
`plugin.mjs` 无条件为其中每一个注册别名。宿主 `dsh-agent-preset-registry` 的 `list()`
返回全量定义且没有 hidden/selectable 字段，`order: 1000` 只能排序、不能隐藏，
于是磁盘上只有当前版本目录的用户也会看到 27 条同名别名，手机窄屏下几乎无法滚动。

本版把别名集合从「所有已发布版本」改为「会话存储里真实引用过的 id」：

- 启动时扫描 `<DSH_HOME>/sessions` 下的会话日志，只解每个日志的**第一帧**（会话头就在第一帧），
  收集其中形如 `openwrite-\d+-\d+-\d+...` 的 `agentPreset` 值，去掉当前版本后注册别名。
  `node:zlib` 的 `zstdDecompressSync` 只解首帧并忽略追加的事件帧，纯文本 `.jsonl` 同样支持；
  每次只读前 256 KB。Node `>=22.15` 起内置 zstd，插件 `engines` 要求 `>=22.19.0`，无需新增依赖。
- 指纹缓存落到 `~/.dsh/openwrite/preset-aliases.json`（会话数 + 最新 mtime），
  存储未变化时不再解压任何日志。
- 扫描整体失败（例如会话根目录不可读）时回退到原来的全量别名表，#105 的恢复能力不会丢失。
- 别名显示名改为可自解释的 `OpenWrite 创作（旧版 0.2.24 · 仅用于恢复历史会话）`，
  不再把内部 id 直接暴露给作者；`order: 1000` 保持沉底。
- 当前发布自身的 id 不再注册别名：它已经以稳定 id `openwrite` 注册，其目录也由本插件管理。
  工作台入口原先固定选择发布 id，现改为优先选择稳定 id `openwrite`，仅在宿主只注册发布 id 时回退，
  因此选择器里 OpenWrite 只剩一条。

实测（真实 DSH `0.2.1-rc.5` 宿主 + Playwright，种子会话引用 `openwrite-0-2-24`）：

- 改动前：选择器列出 `OpenWrite 创作` 加 27 条 `OpenWrite 创作（历史会话 openwrite-0-2-N）`。
- 改动后：只列出 `OpenWrite 创作` 与 `OpenWrite 创作（旧版 0.2.24 · 仅用于恢复历史会话）`。
- 该断言已进入 `scripts/client-boot-smoke.mjs`（`preset-selector-single-entry`）：
  空会话存储下 OpenWrite 必须只出现一次，且不得出现 `历史会话`/`旧版` 条目。

新增回归（`scripts/preset-lifecycle.test.mjs`，真实 zstd 多帧会话日志作夹具）：

- 别名集合跟随会话引用；未引用的发布 id 不进选择器；`standard` 等其它预设被忽略。
- 会话存储不可读时保留全量别名表（#105 不回归）。
- 指纹缓存：存储不变时即使单条日志损坏仍返回缓存结果；新增会话后重新推导。
- 升级不重写会话日志（逐字节比对），作者自定义预设优先，卸载后只移除本插件注册的定义。
