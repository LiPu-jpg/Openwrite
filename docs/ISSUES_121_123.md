成本仅在提供方明确报告时视为已知。`cost_summary.reported_usd` 是已报告部分，`complete=false` 表示存在未知费用；未知值不会伪装成零，也不会把估算当作账单。
取消是协作式操作：`requested` 与 `cancelled` 分开，等待提供方响应时不承诺瞬间停止计费；已收到的流内容与已完成段落会保留，后续请求不再调度。

CI 额外发现并修复归档路径缺陷：排除规则只判断作品内部相对路径，父目录或作品 ID 为 `tmp`、`cache`、`secrets` 或 `exports` 不会再误删大纲等必需内容。四种父目录及四种作品 ID、内部凭据/缓存排除与正文逐字节恢复均有回归。

真实 OpenCode Go 取消测试发现 LiteLLM 的同步包装流没有 `close()`，原清理逻辑未关闭它持有的 HTTP 流。现在取消和流式总时限耗尽时，沿包装流找到本次请求拥有的底层连接并关闭，不关闭共享客户端。直接流和包装流的取消、包装流超时均有回归；真实 Go 测试只有一次服务商请求，取消后已收到的正文保留、HTTP 响应确认关闭，后续请求在调用服务商前被拒绝，`~/my_novel` 文件未改变。实测源码的文件哈希与冻结 Core 提交核对一致。

Windows 全量 CI 又暴露 12 个失败。任务快照读取与写入互斥，并对 Windows 共享冲突做有限重试；正文搜索、工作台、接纳、审稿和历史使用原始 UTF-8 字节计算版本，结构化预览/应用/撤销和场景失败回滚保留行尾。大纲新增内容跟随原有 LF/CRLF。研究进程使用跨平台输出读取和进程树取消，Windows pnpm 脚本通过 Node 入口执行；测试中的 `/bin/echo` 改为真实 Python 子进程。POSIX 权限位断言只适用于 POSIX，凭据不出现在接口的断言在每种系统都运行。新增 20 项专门回归，另将搜索与场景回滚的既有测试扩为 LF/CRLF 两种输入。

字节版本已同步到章节记忆、角色状态索引、导出预检及相关文档接口；搜索检索仍使用规范化行文本，来源版本则保持与原文件一致。旧历史记录缺少格式标记时，兼容其当年的行尾规范化校验，只返回其校验值所代表的文本，不改写旧产物。新记录标为 `source_revision_format=utf8-bytes`，行尾改变也会触发完整性错误。

DSH rc.3 的依赖安装时间固定为发布日之后的 `2026-10-24T00:00:00Z`。原来的未来时间边界会让上游正在发布的一批依赖进入验收，已出现依赖声明早于实际包发布六秒的安装失败；历史依赖图已在 npm 官方 registry 成功解析，最终仍以完整宿主验收为准。

安装回归还发现自动恢复的进度更新会清空上一次后端崩溃原因；现在恢复期间保留该诊断，直到进入 ready 或结束恢复。回归会在新后端启动的边界核对诊断，避免靠观察时机碰巧通过。源码校验从固定 Git 提交归档还原字节并关闭行尾转换，再逐文件比较 wheel；CRLF 检出副本已验证可还原匹配，存在本地改动时拒绝覆盖。

任务快照读取只在文件句柄打开期间互斥，YAML 解析在锁外进行，避免观察进度阻塞后台写入。阻塞解析的并发回归在旧实现失败、修复后通过。异步功能测试允许慢速磁盘下的有限等待，降低轮询频率；错误终态立即失败，超时附最后状态，不把超时或失败任务视为成功。

## 使用补充

项目 `novel_config.yaml` 可配置：

```yaml
previous_chapter_mode: tail  # full / tail / summary，默认 full
previous_chapter_tail_chars: 800
outline_extra_keys:
  - 故事线
  - 视角人物
```

在章纲中按 `> 故事线: 雨钥线` 填写扩展字段。summary 模式要求上一章有与当前正文匹配的有效章节记忆；不能用过期摘要继续写作。

只组装不生成：`novel_write_chapter {chapter_id, dry_run:true, guidance, target_words}`。
普通写作立即返回 task_id，用 `novel_task_get` 查询，用 `novel_task_cancel` 请求取消。
取消后使用 `resume_from_draft:true` 续写最近可用的部分稿；原上下文或源文件变动时会拒绝自动续写，需先检查草稿。
新运行通过 `resumed_from_run_id` 指向旧运行，费用记录分别保留。

历史运行：`novel_chapter_run_action {action:"list", chapter_id, include_archived:true}`。
删除章节会把原运行及产物移动到 `data/chapter_deletions/<operation>/`，不会删除这些历史；返回的 `archive_directory` 和 artifact 指向归档位置。
当前没有自动清除运行的保留策略。列表默认 20 条、最多 200 条，可按章节和时间筛选；这不是磁盘保留上限。

## 三套阶段的对应关系

| 语义 | Chapter Run V2 | 工作流页 | DoG 交付图 |
| --- | --- | --- | --- |
| 输入准备 | context / plan | context_assembly | writing 的上游依据 |
| 草稿生成、事实提取和入库 | draft / fact_extract / settle / validate / commit | writing | writing 检查已入库正文及版本 |
| 执行一次模型审稿 | review（completed 只表示调用与保存完成） | review | review 检查当前正文对应的审稿结论 |
| 作者核对验收影响 | 验收台账中的 acknowledge | user_confirm | closure 的交付依据之一 |
| 文风/压缩诊断 | 上下文与写作产物 | styling / compression | 不直接等于交付通过 |
| 修订到最终交付 | 修订记录与再次审稿 | 不由单个绿色步骤代表 | revision / application / rereview / closure |

`gate_status` 表示硬门禁，`delivery_status` 表示完整交付结论；硬门禁通过仍可能因未评范围、证据不足或质量不足而不能交付。
部分审稿使用 `scope_status=partial`、`scope_quality_score`、`scope_passed` 和 `unreviewed_dimensions`；完整章总分保持 null，完整交付仍需全范围检查。
