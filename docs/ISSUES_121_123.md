## 使用补充

项目 `novel_config.yaml` 可配置：

```yaml
previous_chapter_mode: tail  # full / tail / summary，默认 full
previous_chapter_tail_chars: 800
outline_extra_keys:
  - 故事线
  - 视角人物
```

在章纲中按 `> 故事线: 雨钥线` 填写扩展字段。summary 模式要求上一章有与当前正文匹配的有效章节记忆；不能用过期摘要继续写作。

只组装不生成：`novel_write_chapter {chapter_id, dry_run:true, guidance, target_words}`。
普通写作立即返回 task_id，用 `novel_task_get` 查询，用 `novel_task_cancel` 请求取消。
取消后使用 `resume_from_draft:true` 续写最近可用的部分稿；原上下文或源文件变动时会拒绝自动续写，需先检查草稿。
新运行通过 `resumed_from_run_id` 指向旧运行，费用记录分别保留。

历史运行：`novel_chapter_run_action {action:"list", chapter_id, include_archived:true}`。
删除章节会把原运行及产物移动到 `data/chapter_deletions/<operation>/`，不会删除这些历史；返回的 `archive_directory` 和 artifact 指向归档位置。
当前没有自动清除运行的保留策略。列表默认 20 条、最多 200 条，可按章节和时间筛选；这不是磁盘保留上限。

## 三套阶段的对应关系

| 语义 | Chapter Run V2 | 工作流页 | DoG 交付图 |
| --- | --- | --- | --- |
| 输入准备 | context / plan | context_assembly | writing 的上游依据 |
| 草稿生成、事实提取和入库 | draft / fact_extract / settle / validate / commit | writing | writing 检查已入库正文及版本 |
| 执行一次模型审稿 | review（completed 只表示调用与保存完成） | review | review 检查当前正文对应的审稿结论 |
| 作者核对验收影响 | 验收台账中的 acknowledge | user_confirm | closure 的交付依据之一 |
| 文风/压缩诊断 | 上下文与写作产物 | styling / compression | 不直接等于交付通过 |
| 修订到最终交付 | 修订记录与再次审稿 | 不由单个绿色步骤代表 | revision / application / rereview / closure |

`gate_status` 表示硬门禁，`delivery_status` 表示完整交付结论；硬门禁通过仍可能因未评范围、证据不足或质量不足而不能交付。
部分审稿使用 `scope_status=partial`、`scope_quality_score`、`scope_passed` 和 `unreviewed_dimensions`；完整章总分保持 null，完整交付仍需全范围检查。
