## #140：自备 Python

在 managed 模式增加 `pythonPath`，或通过 `OPENWRITE_PYTHON` 选择解释器；显式配置优先。
可用 `pythonModulePaths` 列出作者准备的依赖目录，对应报告中的 Android `pyroot`。
选定解释器后，即使 manifest 没有当前平台，也不会下载 uv 或 python-build-standalone。

插件校验随包 Core/依赖清单，将纯 Python Core wheel 解包到自己的环境目录，
用所选解释器导入检查 Python >=3.10、Core 和 API 版本，再启动已有的 stdio 鉴权后端。
不执行 pip、不自动解析依赖、不修改作者解释器；显式依赖目录与解释器路径参与缓存标识。
`-I` 隔离、UTF-8 和 `-B` 禁止字节码写入同时生效。
共享构建的原生库搜索路径仅在自备解释器模式下传入；凭据仍按原有环境白名单过滤。

依赖缺失或不匹配时给出诊断，保留旧 active 记录，不回退到隐式下载。
每次使用已有环境启动前也重做导入检查，以免作者改动依赖后仍把旧缓存当成可用环境。
启动后的鉴权、随机端口、健康检查、取消、重启上限和 owned-process 清理继续使用原有生命周期。

真实 Python 的 7 项新增集成覆盖：启动/鉴权/恢复及依赖目录不写入；缺依赖与旧环境保留；
缓存环境重新检查；Core 版本不匹配；环境变量与配置优先级；绝对路径校验；安装取消。
完整 managed 工具与生命周期测试本地 **41 passed / 0 skipped**。
真实随包 Core 5.8.20 的健康接口、鉴权和 Studio 静态资源另通过本地自备解释器验收；
相同验收加入正式安装矩阵，新增集成测试也对确切 tarball 内代码执行。

## #142：旧包选择

报告环境是 DSH 0.2.1-rc.3；实际报错版本为 OpenWrite 0.2.25。
0.2.25 的 peer 声明确实不覆盖该宿主。官方 npm 当前 latest 0.2.28 的根包及三个内嵌子包
均声明精确支持 0.2.1-rc.3；不能把旧包拒绝诊断改成放宽新包兼容范围。

使用本地模拟 registry、真实 pnpm 和隔离 profile，构造 0.2.25 精确依赖、registry latest 0.2.28：

| 操作 | 结果 |
| --- | --- |
| install 初始精确依赖 | 0.2.25 |
| add dsh-openwrite | 仍为 0.2.25 |
| add dsh-openwrite@latest | 0.2.28 |

这证明一种能导致相同错误的旧包选择条件；报告者具体的 spec/锁/registry 缓存仍需原场景确认。
商城本身属于外部项目，OpenWrite 不改变其全局安装策略。

本仓库补修：停机升级工具将裸 `dsh-openwrite` 规范为显式 `dsh-openwrite@latest`，
精确版本与本地 tarball 继续保持原意。doctor 单独显示 requested spec、resolved version、
诊断工具版本及精确重装目标，避免只看商城目录或笼统的“已安装”。对应维护/升级测试本地 **20 passed**。
安装指南补充官方 registry 检查、停机备份和已验收 0.2.28 的精确升级路径。
未给旧包添加兼容豁免，也未清空用户缓存、profile 或会话。
